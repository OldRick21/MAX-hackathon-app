# Изолированный эксперимент с iframe

Самостоятельный тест, не подключённый к основному приложению. Вся папка переносится в другой репозиторий без изменений. Использует собственный Compose-проект `max-iframe-probe`, без бота, токенов и базы данных.

## Запуск

Из этой папки:

```bash
docker compose up -d --build
```

Откройте http://127.0.0.1:8081. Если Docker требует прав администратора, добавьте `sudo` перед командами Docker.

Backend выдаёт каталог из двух демонстрационных сервисов и их HTML. Можно добавлять произвольное число экземпляров, но iframe загружается только по кнопке «Открыть». Проверяются исполнение JS, двусторонний обмен сообщениями, действия пользователя и выгрузка. Ресурсы устройства ограничивают число одновременно открытых клиентов.

## Проверка внутри MAX

Адрес localhost подходит только для обычного браузера на этой машине. Для MAX тесту нужен отдельный публичный HTTPS-адрес и тестовый бот с этим адресом мини-приложения. Основной бот и его привязка не меняются.

Для публикации на текущем VDS используется отдельный порт 8443 и существующий сертификат IP. Основной сайт на 443 не меняется. На сервере из папки `iframe-probe` выполните:

```bash
sudo docker compose -f compose.yaml -f compose.https.yaml config --quiet
sudo docker compose -f compose.yaml -f compose.https.yaml up -d --build
sudo docker compose -f compose.yaml -f compose.https.yaml exec web nginx -t
curl https://195.133.197.144:8443/api/demo/services
```

Публичный адрес теста: `https://195.133.197.144:8443/`. Входящий TCP 8443 должен быть разрешён в сетевом экране сервера и панели провайдера. Этот URL нужно временно указать в настройках мини-приложения существующего бота; сохраните предыдущий URL для возврата.

Сертификат подключается из `/var/lib/max-miniapp/letsencrypt`, приватный ключ остаётся на сервере. После продления сертификата перезагрузите тестовый Nginx:

```bash
sudo docker compose -f compose.yaml -f compose.https.yaml exec web nginx -s reload
```

Обычный запуск без `compose.https.yaml` по-прежнему публикует только локальный порт 8081. HTTPS-конфигурация сама завершает TLS и передаёт правильную схему backend для проверки origin сообщений.

Сценарий: открыть через тестового бота, загрузить 1, затем 5–10 клиентов, нажать кнопки внутри, выгрузить и открыть повторно. Через «Показать отчёт» скопировать результат вместе с версией MAX и ОС. Работа в обычном браузере не доказывает поддержку внутри MAX.

Исследование, ограничения и запасной вариант описаны в [RESEARCH.md](RESEARCH.md).

## Удаление

Сначала из этой папки остановите тест:

```bash
docker compose down --rmi local
```

Затем удалите папку `iframe-probe`. Основной Compose и приложение не затрагиваются.
