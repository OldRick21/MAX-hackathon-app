# Курсовые работы — тестовый сторонний сервис

Свой сервис вуза на шаблоне SDK (`docs/services/sdk/service-template`). Работает независимо от платформы: свой процесс, своя база и файлы, свой интерфейс внутри приложения. К платформе подключается через админку как «Свой сервис» с кодом `coursework`.

Что умеет: студент отправляет PDF и выбирает проверяющего, преподаватель принимает работу или возвращает на доработку, студент загружает новую версию; менеджер курсовых (роль `coursework_manager`) видит и удаляет все работы. Имена пользователи указывают прямо в сервисе — другие сервисы платформы он не вызывает.

## Запуск на сервере платформы (демо)

Нужно DNS-имя: ядро не принимает IP-адреса для своих сервисов. Подойдёт бесплатное `coursework.195-133-197-144.sslip.io` — оно само указывает на IP сервера.

1. **Сертификат.** Основной Nginx платформы отвечает на проверки Let's Encrypt для любого имени, поэтому из корня проекта:

   ```bash
   sudo docker compose run --rm certbot certonly --webroot -w /var/www/acme \
     -d coursework.195-133-197-144.sslip.io --cert-name coursework
   ```

2. **Одобрение хоста.** Поддержка платформы: карточка вуза → «Одобренные хосты» → `coursework.195-133-197-144.sslip.io`.
3. **Регистрация.** Администрирование → «Сервисы» → «Подключить свой сервис»: название «Курсовые работы», код `coursework`, все профили, адреса `https://coursework.195-133-197-144.sslip.io:9443/api/v1` и `https://coursework.195-133-197-144.sslip.io:9443`.
4. **Ключ.** В карточке сервиса «Выдать ключ» и скопировать строки.
5. **Запуск.**

   ```bash
   cd test-data/coursework
   cp .env.example .env
   nano .env            # вставить строки из админки, проверить COURSEWORK_HOST и порт
   chmod 600 .env
   sudo docker compose up -d --build
   sudo docker compose logs --tail=50 app    # onboarding complete
   ```

   Откройте порт 9443 в файрволе. Через минуту шаг «Запуск сервиса» в админке станет «готово».
6. **Включение.** В карточке — «Включить». Курсовые появятся в «Все сервисы».
7. Роль «Менеджер курсовых» назначается в админке («Роли» → «Курсовые работы» → профиль «Администратор»).

На отдельном сервере вуза всё так же, только сертификат выпускается там (например, `certbot --standalone`), а `CORE_URL` и `SHELL_ORIGIN` указывают на платформу.

Остановка: `sudo docker compose down` (данные остаются в volume `coursework_coursework-data`).
