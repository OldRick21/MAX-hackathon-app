# Сервис курсовых: реализация

Код — `test-data/coursework/`: тестовый сторонний сервис на шаблоне SDK, подключается как сервис вуза типа `coursework` и запускается своим контейнером — [README](../../../test-data/coursework/README.md). Контракт — [SPEC.md](SPEC.md) и [OPENAPI.yaml](OPENAPI.yaml); ниже — отличия.

## Отличия от контракта

- Размещение: один контейнер — один вуз, ключ из `.env`; меню и роль `coursework_manager` (`coursework.manage`) сервис публикует сам. Права — по контракту: admin видит и удаляет работы только с `coursework.manage`.
- Интерфейс — страница `/coursework` (iframe, SDK §7). Имён в API нет (как в контракте): участники показываются по UUID, проверяющий указывается по UUID. В оболочке, если подключены «Люди», экран курсовых рисуется своими средствами и показывает имена из анкет.
- Проверяющий при загрузке должен иметь профиль `teacher` (проверка через ядро) и не совпадать с автором.
- Весь multipart ≤ 21 MiB по фактическим байтам, файл ≤ 20 MiB; проверяются тип `application/pdf`, сигнатура `%PDF-` и `startxref`/`%%EOF` в хвосте — отсев не-PDF, не антивирус.
- Лимит загрузок (10 в минуту, 2 одновременно) хранится в памяти процесса: один worker.
- Удаление логическое; файл уходит в очередь очистки. Замена файла откладывает удаление старой версии на 24 часа. Очистка раз в час: брошенные загрузки старше 10 минут, файлы очереди без живой ссылки, сироты старше суток.
