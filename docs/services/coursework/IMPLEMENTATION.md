# Сервис курсовых: реализация

Код — `test-data/coursework/`: тестовый сторонний сервис на шаблоне SDK, подключается как «Свой сервис» (`custom.coursework`) и запускается отдельно — [README](../../../test-data/coursework/README.md). Контракт — [SPEC.md](SPEC.md) и [OPENAPI.yaml](OPENAPI.yaml); ниже — отличия.

## Отличия от контракта

- Тип в ядре — `custom.coursework`, а не `coursework` из каталога: сервис подключается общим механизмом своих сервисов. Права — `coursework.manage`, роль `coursework_manager`.
- Интерфейс — собственная страница `/coursework` внутри приложения (iframe, протокол SDK §7), а не экран оболочки.
- Сервис не обращается к «Людям»: пользователи указывают имя в сервисе (`GET/PUT /api/v1/coursework/me`), список проверяющих — `GET /api/v1/coursework/teachers`, имена в списке работ — поле `people`.
- Проверяющий при загрузке должен иметь профиль `teacher` (проверка через ядро) и не совпадать с автором.
- Весь multipart ≤ 21 MiB по фактическим байтам, файл ≤ 20 MiB; проверяются тип `application/pdf`, сигнатура `%PDF-` и `startxref`/`%%EOF` в хвосте — отсев не-PDF, не антивирус.
- Лимит загрузок (10 в минуту, 2 одновременно) хранится в памяти процесса: один worker.
- Удаление логическое; файл уходит в очередь очистки. Замена файла откладывает удаление старой версии на 24 часа. Очистка раз в час: брошенные загрузки старше 10 минут, файлы очереди без живой ссылки, сироты старше суток.
