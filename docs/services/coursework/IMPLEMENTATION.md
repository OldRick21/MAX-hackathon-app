# Сервис курсовых: реализация

Код — `test-data/coursework/` (тестовый сторонний сервис, будет переписан отдельно). Контракт — [SPEC.md](SPEC.md) и [OPENAPI.yaml](OPENAPI.yaml); здесь то, что в реализации уточнено или упрощено.

## Подключение (SPEC §2, CORE_API_SPEC §7)

1. Поддержка платформы одобряет DNS-имя вуза («Поддержка платформы» → карточка вуза → «Одобренные хосты»). IP-адреса ядро не принимает.
2. Администратор вуза с `services.manage` регистрирует сервис: «Сервисы» → «Подключить сервис» → «Курсовые работы», адреса API и клиента на одобренном хосте. Экземпляр создаётся выключенным с пустым меню.
3. Администратор с `credentials.manage` нажимает «Выдать ключ». Админка показывает один раз готовый блок `.env`: `CORE_URL`, `SHELL_ORIGIN`, `COURSEWORK_CLIENT_ID`, `COURSEWORK_CLIENT_SECRET`, `COURSEWORK_API_BASE_URL`, `COURSEWORK_CLIENT_BASE_URL`.
4. Сервер вуза запускает сервис с этими настройками. При старте сервис обменивает ключ на machine-токен, создаёт роль `coursework_manager` и публикует меню (`PUT .../manifest` с `If-Match`). При недоступности ядра повторяет с растущей паузой до 5 минут. Состояние видно в `GET /api/v1/health` (`onboarding`).
5. Карточка сервиса в админке показывает шаги и их состояние; кнопка «Включить» активна, когда меню опубликовано.

`institution_id` и `service_id` сервис берёт из ответа ядра на обмен ключа, а не из настроек. Токен другого экземпляра — `404`.

## Размещение

- Процесс на порту 8400 (UID 10005), SQLite `/data/coursework.db`, файлы `/data/files/<вуз>/<экземпляр>/<работа>/<версия>-<random>.pdf`, временные загрузки `/data/tmp`.
- Экраны рисует оболочка и обращается к API напрямую: CORS разрешён только `SHELL_ORIGIN`, без cookies, с нужными заголовками и раскрытием `ETag`, `Location`, `X-Request-ID`, `Retry-After`, `Content-Disposition`. HTML-entrypoint `/coursework` не реализован.
- В основном Compose сервис собран профилем `coursework` для демо на том же сервере; пример HTTPS-входа — `web/configs/coursework-nginx.conf.example`.

## Уточнения

- Весь multipart считается по фактическим байтам (≤ 21 MiB), файл — ≤ 20 MiB. Проверяются заявленный тип `application/pdf`, сигнатура `%PDF-` и наличие `startxref`/`%%EOF` в хвосте. Это отсев не-PDF, не антивирус и не полный разбор структуры.
- Форма должна содержать ровно ожидаемые поля; лишнее поле (например, `student_id`) — `422`.
- Проверяющий при POST должен иметь профиль `teacher` (проверка через ядро) и не совпадать с автором.
- Повторная авторизация выполняется после загрузки, перед транзакцией записи.
- Лимит загрузок (10 в минуту, 2 одновременно на пользователя) хранится в памяти процесса: сервис работает одним worker.
- Список — по `created_at` по убыванию, фильтр `status`, курсор подписан ключом сервиса и привязан к пользователю, профилю и фильтру.
- Удаление логическое (`deleted=1`); файл ставится в очередь очистки. Замена файла откладывает удаление старой версии на 24 часа.
- Очистка раз в час: брошенные загрузки старше 10 минут, файлы из очереди без живой ссылки, сироты без ссылки старше суток.
