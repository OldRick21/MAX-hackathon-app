# Сервис расписания

Версия `0.1.0`, 26 сентября 2026. Облачный сервис групп и конкретных занятий. Контракт разделён без изменения операций; код не реализуется.

[OpenAPI](OPENAPI.yaml) · [Эндпоинты](ENDPOINTS.txt) · [Общее и SDK](../sdk/SPEC.md) · [Навигация](../INDEX.md).

Этот комплект содержит 13 собственных операций. Полный API дополняется тремя общими операциями [SDK](../sdk/OPENAPI.yaml). Все входящие защищённые запросы используют ServiceBearer и online introspection по общим правилам.

## 1. Размещение, права и меню

Один процесс типа schedule обслуживает логические экземпляры вузов по [облачной схеме](../CLOUD_RUNTIME_SPEC.md). Учебные данные принадлежат этому сервису; членства и профили — ядру.

- api_base_url: `https://schedule.platform.example/api/v1`.
- client_base_url: `https://schedule.platform.example`.
- Поддерживаемые профили: admin, teacher, student.

| Permission | Действие профиля admin |
| --- | --- |
| `schedule.read_all` | Читать все группы и занятия экземпляра |
| `schedule.write` | Создавать, изменять и удалять занятия |
| `groups.manage` | Менять группы, читать и заменять состав |

Начальная роль `schedule_editor` содержит все три permission, allowed_profiles=[admin]. Платформа создаёт её при установке; owner назначает конкретному user/profile/instance через administration. Обычный admin без роли доступа к расписанию не получает. Write не подразумевает read; нестандартной роли для UI нужны права чтения и получения ETag.

| ID меню | Название | Путь | Профили | required_permissions | order |
| --- | --- | --- | --- | --- | --- |
| schedule | Расписание | /schedule | student, teacher | [] | 0 |
| schedule_admin | Расписание | /schedule | admin | [schedule.read_all] | 0 |

Базовые права student/teacher не требуют роли и ограничены своим расписанием. SDK проверяет профиль/permissions, а принадлежность группы/занятия проверяет сервис.

## 2. Группы и занятия

Группа — UUID и имя. Состав — отдельный агрегат `group_id + user_ids` с отдельным ETag. Один student может состоять максимум в одной группе текущего schedule instance. Это осознанное упрощение MVP; подгрупп, факультативных групп и истории состава нет. До назначения группы расписание студента пустое, не ошибочное.

Группы создаёт/переименовывает/удаляет admin с groups.manage. PUT состава атомарно заменяет список до 500 UUID; все должны сейчас иметь student по ядру. Проверка существования профиля происходит перед локальной транзакцией и не даёт распределённой гарантии против одновременного удаления membership. Такое удаление блокирует сервисную сессию; оставшаяся строка группы доступа не даёт. GET состава для редактора показывает сохранённые UUID, включая устаревшие, чтобы их можно было удалить. Возвращать чужие ФИО из ядра этот endpoint не пытается.

Перевод между группами — сначала удалить из старой, затем добавить в новую. В промежутке расписание может быть пустым; отдельный API атомарного перевода для демо не нужен. Уникальный индекс по `(institution_id, service_id, user_id)` не допускает две группы при гонке. Удалить непустую группу или группу, упомянутую любым занятием, нельзя: 409 GROUP_IN_USE.

Занятие — конкретный интервал UTC, заголовок, место/описание, непустые списки групп и teacher UUID. При записи start < end, ссылки на группы того же экземпляра, преподаватели имеют актуальный teacher. Время хранится UTC Z; клиент отображает в выбранной настройке часового пояса, по умолчанию Europe/Moscow. Нового поля часового пояса в вуз ядра не добавляем. Повторяющиеся недели разворачиваются редактором в отдельные занятия. Пересечения занятий допускаются; автоматическое составление/проверка конфликтов вне MVP.

Студент видит события своей **текущей** группы; преподаватель — события со своим UUID среди teacher_ids; admin с schedule.read_all — все. Фильтр по группе/преподавателю только сужает этот набор. Диапазон обязателен, не более 31 суток, пересечение с ним считается как `starts_at < to AND ends_at > from`; период может включать отменённые события. Прямой запрос недоступного события — 404. Порядок — starts_at, затем id.

PUT меняет всё занятие; `status=cancelled` сохраняет отмену для пользователей. DELETE применяется для ошибочной записи и убирает её из выдачи. Никаких push-уведомлений или интеграции с ботом этот контракт не обещает.

Ошибки порядка/диапазона времени — 422 INVALID_TIME_RANGE; ссылки на несуществующую группу или пользователя без teacher/student — 422 INVALID_REFERENCE. Проверка UUID пользователя выполняется через machine API профилей ядра, а не прямым доступом к его БД.

### 2.1. Импорт из файла (расширение реализации)

Администратор с `schedule.write` (и преподаватель, которому включили правку) загружает занятия файлом: кнопка «Импорт» в разделе «Расписание». Формат **один** — таблица занятий; тип файла любой из: JSON, Excel `.xlsx`, выгрузка 1С `.csv`/`.txt` (разделитель `;`, табуляция или запятая; UTF-8 или Windows-1251), XML. Старые `.xls` и табличный документ 1С `.mxl` не читаются — их сохраняют как `.xlsx` или `.csv`.

| Столбец | Другие названия | Значение |
| --- | --- | --- |
| Дата | date, День | `29.09.2026` или `2026-09-29` (или дата Excel) |
| Начало | Время начала, start | `08:30`, местное время вуза |
| Конец | Окончание, Время окончания, end | `10:05` |
| Дисциплина | Предмет, Название, Занятие, title | до 200 символов |
| Группы | Группа, groups | названия групп вуза через запятую или `;` |
| Преподаватели | Преподаватель, teachers | ФИО как в заявке на вступление или UUID, через запятую |
| Аудитория | Место, Кабинет, location | пусто — онлайн |
| Комментарий | Описание, Примечание, description | необязательно |
| Статус | status | пусто или «проводится»; «отменено» |

В CSV и Excel заголовки — первая узнаваемая строка (строки шапки 1С выше неё пропускаются). В JSON — список объектов или `{"events": [...]}` с теми же ключами (русскими или английскими). В XML — элементы-строки, у которых столбцы заданы атрибутами или вложенными элементами (`<Занятие Дата="…" Начало="…" …/>`). Примеры — в [import-examples](import-examples).

`POST /api/v1/schedule/import?name=<имя файла>&dry_run=true|false`, тело — содержимое файла (`application/octet-stream`, до 2 МБ, до 2000 занятий):

- `dry_run=true` — только проверка: `{total, to_create, duplicates, errors: [{row, message}], preview, created: 0}`; `row` — номер строки в файле;
- `dry_run=false` — загрузка **всё или ничего**: при любой ошибке `422 INVALID_IMPORT` с ошибками в `details`, ничего не записано;
- занятие с тем же названием, временем и группами, что уже есть в расписании, пропускается (`duplicates`) — повторная загрузка файла не создаёт дублей;
- нечитаемый файл, неподдерживаемый тип, нет строки заголовков — `422 INVALID_FILE`; нет права — `403`.

Группы ищутся по названию (без учёта регистра) в справочнике ядра; преподаватели — по имени среди участников вуза с профилем «Преподаватель». Если имя встречается у нескольких преподавателей, строка — ошибка: укажите UUID.

## 3. Версии и хранение

Во всех ключах tenant означает `(institution_id, service_id)`.

| Объект | Ограничения |
| --- | --- |
| Группа | PK tenant+group_id; UNIQUE tenant+trim/casefold(name); revision метаданных |
| Состав | UNIQUE tenant+student_id; составной FK на группу; своя revision на группу |
| Занятие | PK tenant+event_id; revision; составные FK связей на группы того же tenant |

POST группы/занятия требует Idempotency-Key; изменение существующего ресурса — If-Match. Версия состава отдельна от имени группы. SDK предоставляет общий механизм, сервис выполняет изменение, запись версии и idempotency в своей транзакции.

Снятие профиля/membership блокирует запросы через ядро, но не стирает строки автоматически. При повторном добавлении того же UUID в вуз прежние связи вновь применяются; истории периодов членства в MVP нет. Сервисы не вызывают user-profile для обязательного получения имён; ссылки остаются UUID. Импорт, подгруппы и автоматическое составление расписания не входят в MVP.

## 4. Приёмка

1. Student без группы получает пустое расписание; teacher видит только свои занятия, чужой event_id возвращает 404.
2. Фильтры никогда не расширяют доступ; отменённые занятия видны в разрешённом диапазоне.
3. Конкурентное назначение студента в две группы не проходит; устаревший ETag даёт 412.
4. Нельзя удалить непустую/используемую группу или связать занятие с группой другого экземпляра.
5. Повтор POST с одинаковыми ключом и телом не создаёт дубликат; иное тело даёт 409.
