# Сервис-заглушка расписания

Вымышленные пары, без собственного backend и персональных данных. Протокол Service SDK: init/ready/context, обновление сессии, завершение. Проверяются источник, origin и channel; токены не сохраняются и не выводятся.

Размещён на `https://195.133.197.144:8443` — отдельный origin от оболочки. Порт 8443 должен быть доступен с устройства. Использует существующий сертификат IP. CSP разрешает родителей ядра и MAX Web. API URL в реестре — заготовка, сервис не делает к нему запросы.

После доставки файлов на сервер:

```bash
cd /opt/MAX-hackathon-app
sudo docker compose up -d --build backend web
sudo docker compose exec backend python seed_demo.py 1eaa04e2-4843-4949-bfcf-ac7d3270e7bd
```

Команда требует существующего пользователя, создаёт тестовый вуз и сервис, добавляет только student. Повторный запуск не дублирует записи, существующие назначения сохраняются. После запуска заново откройте приложение MAX → Тестовый университет → Расписание — демо. Кнопка в сервисе проверяет refresh через ядро.

Демо изолировано файлами в этой папке, `backend/seed_demo.py`, отдельным server-блоком Nginx и портом/volume в Compose. Не удаляйте общие volumes базы при отключении демо.
